## 5. Acceptance criteria

- [x] Classes and entities exist for User, StudentRecord, ModelVersion, Prediction, FollowUpAction, FollowUpStatusHistory, and AuditEvent
- [x] Attributes and important operations are shown on the class diagram
- [x] Primary and foreign keys and optional (nullable) keys are shown on the ERD
- [x] Override or dismissal is represented on the prediction (`decision_status`, `decision_reason`, deciding user, decision time)
- [x] Prediction records the model version that produced it (FR-16)
- [x] Follow-up status history is stored separately from the follow-up (FR-23)
- [x] **Multiplicities (for example 1 and 0..\*) are shown on every association** (required by the course instructions)
- [x] Enumerations (UserRole, OutcomeClass, DecisionStatus, FollowUpStatus) are defined on the class diagram
- [x] The class diagram can store the *overridden outcome*, not only the reason (FR-19: "keep the original estimate on record")
- [x] Multiple notes on a follow-up can be stored without overwriting earlier notes (FR-23)
- [x] The model's confusion matrix can be stored for the limitations page (FR-11, FR-30)
- [x] Class diagram and ERD agree with each other and with `docs/architecture.md`
- [x] A team member other than the prompt author has reviewed the output
